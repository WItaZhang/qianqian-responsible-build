# 复盘

一次只处理这一个任务。目标有两个：留下一条可以拿来讲的记录；让同样的错误不再发生。

## 1. 回顾这个任务
根据对话和 `git log` / `git diff` 整理（不确定的地方问用户，不要编）：
- 任务是什么
- AI 做了什么，用户做了什么（定 spec、审查、接管了哪里）
- 出过什么错：症状是什么、怎么发现的（测试 / 审查员 / 用户自己看出来的）、根本原因是什么
- 纠正了几轮，第一次交付是否就通过了验收

## 2. 追加一条日志
追加到全局日志 `~/.claude/ai-log.md`（没有就创建）。所有项目共用这一个文件，方便面试前汇总；不要写进项目仓库。项目名用 git 仓库根目录的文件夹名。格式：

```markdown
## <日期> [<项目名>] <任务名>
- 任务：
- 分工：AI 做了… / 我做了…
- 出错与发现：
- 纠正轮数：  首次交付是否通过验收：是/否
- 沉淀：<这次加了什么规矩或检查；没有就写"无">
```

## 3. 决定这次的错误要不要变成规矩
对每个错误问一句：它下次还会犯吗？
- **不会**（偶发、需求本身没说清）→ 不加规矩，只记日志。
- **会，而且是第一次出现** → 在项目 `CLAUDE.md` 的"踩过的坑"下加一行，写成具体的指令。
- **CLAUDE.md 里已经写过，还是又犯了** → 文字管不住了，提议升级成自动检查：一条测试、一条 lint 规则，或者加进 `.claude/verify.sh`。说明具体怎么加，用户同意后再改。

## 4. 收尾
- 如果项目 `CLAUDE.md` 超过 200 行，指出可以删掉的过时条目。
- 提醒用户：如果这个任务锁了测试，在终端里先 cd 到项目目录，再运行 `~/.claude/hooks/lock-tests.sh --unlock` 解锁。
